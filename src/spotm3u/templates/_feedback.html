{# Shared transient feedback for asynchronous operations. Every async action reports itself through ``window.SpotM3UFeedback`` instead of building its own toast, so saves, update downloads and failures all look and behave the same: an icon from the same set the track statuses use (see ``_status_icons.html``), a short headline, one muted line of detail, and at most one action button. Tones match the vocabulary the rest of the UI speaks — success, warning, error — and each carries its own colour pair and how long it stays up. Errors are deliberately longer-lived than successes: a failure the user might have missed is worse than a stale confirmation. Toasts cover transient events only; errors that concern the page itself stay as persistent inline messages. Messages here are user-facing text. Technical detail belongs in the console (and the SpotM3U log), so callers log the caught error themselves. #}
